# 翻转链表：把一个「简单」问题讲透

> 翻转链表是算法学习的「第一道门槛」：代码只有几行，却能同时考察**指针操作、递归思维、复杂度权衡**三件事。
> 本文不满足于"会写"，而是把同一个问题的 **4 种实现**摆在一起，讲清每种背后的思想、复杂度的来源，以及工程上如何选择。

---

## ① 一句话思想

> **翻转链表 = 逐个把节点从旧链表"摘下来"，头插到新链表上。**

所有实现都是这句直觉的不同表达——区别只在于：用**指针**摘（迭代）、用**函数调用栈**摘（递归）、还是用**显式数据结构**摘（栈辅助）。

---

## ② 可视化动画：指针到底怎么动

![翻转链表迭代法执行过程动画](/algorithms/assets/reverse-linked-list/reverse-iter.gif)

看动画时建议盯住三个问题：

1. 每一轮 `curr.next` 的指向**先被暂时保存**（绿色 `next`），再被改写——为什么必须先暂存？
2. 弧线（已反转区）是如何一轮轮变长的？
3. 循环结束时为什么返回的是 `prev` 而不是 `curr`？

<details>
<summary>💭 想一想：为什么必须先暂存 next？</summary>

**答案**：`curr.next = prev` 这一行会把 `curr` 原来指向后继的指针**覆盖掉**。如果不先暂存，旧的 `curr.next`（后半段链表的头）就永远找不回来了——链表从这里"断链"，后半段整体丢失。

**暂存 next 不是可选项，是保命动作。**

</details>

## ③ 四种实现

以下代码均为 Go，`ListNode` 定义：

```go
type ListNode struct {
    Val  int
    Next *ListNode
}
```

### 实现 1：迭代法（双指针）—— 工程首选

```go
func reverseList(head *ListNode) *ListNode {
    var prev *ListNode = nil
    curr := head
    for curr != nil {
        next := curr.Next // 1. 暂存后继，防断链
        curr.Next = prev  // 2. 反转当前指针
        prev = curr       // 3. prev 前移
        curr = next       // 4. curr 前移
    }
    return prev
}
```

**不变量**：循环的每一轮开始时，`prev` 是已反转部分的头，`curr` 是未反转部分的头，两段链表互不相连。循环结束时 `curr == nil`，`prev` 恰好是整条链的新头。

### 实现 2：递归法 —— 后序思维的优雅表达

```go
func reverseList(head *ListNode) *ListNode {
    if head == nil || head.Next == nil {
        return head // 递归基：空链或只剩一个节点
    }
    newHead := reverseList(head.Next) // 1. 先把后面整段翻转好
    head.Next.Next = head             // 2. 让后继指回自己
    head.Next = nil                   // 3. 自己成为尾，断开旧指向
    return newHead                    // 4. 新头一路透传回去
}
```

**关键理解**：`reverseList(head.Next)` 执行完后，`head` 之后的所有节点已经翻转完毕（比如 1→2→3→4→5 中调用返回后变成 5→4→3→2，此时 `head`=1 还挂在外面）。第 2、3 行做的事就是把 1 接到尾巴上：`head.Next.Next = head` 让 2 指回 1。

<details>
<summary>💭 想一想：递归法中 <code>head.Next = nil</code> 可以省略吗？</summary>

**答案**：不可以。省略后原头节点（1）的 `Next` 仍指向 2，而 2 已被翻转为指向 1，形成 **1 ⇄ 2 的环**，链表不再是合法的线性结构，遍历会死循环。

</details>

### 实现 3：头插法（dummy 哨兵）—— 最贴合"一句话思想"

```go
func reverseList(head *ListNode) *ListNode {
    dummy := &ListNode{}          // 哨兵节点，新链表的头
    curr := head
    for curr != nil {
        next := curr.Next  // 暂存
        curr.Next = dummy.Next // 摘下来，插到新链表头
        dummy.Next = curr
        curr = next
    }
    return dummy.Next
}
```

每轮循环把一个节点"摘下来头插"，`dummy.Next` 永远指向新链表当前的头。逻辑直白，与"逐个摘下来头插"的直觉一一对应，代价是多一个哨兵节点。

### 实现 4：栈辅助法 —— 直觉但浪费

```go
func reverseList(head *ListNode) *ListNode {
    if head == nil {
        return nil
    }
    stack := []*ListNode{}
    for p := head; p != nil; p = p.Next {
        stack = append(stack, p) // 全部压栈
    }
    dummy := &ListNode{}
    curr := dummy
    for len(stack) > 0 {
        node := stack[len(stack)-1] // 逆序弹出
        stack = stack[:len(stack)-1]
        curr.Next = node
        curr = curr.Next
    }
    curr.Next = nil // 关键：原头节点的 Next 必须置空，否则成环
    return dummy.Next
}
```

最"人类直觉"的写法（倒着拿出来接上），但多花 O(n) 栈空间，且最后 `curr.Next = nil` 极易遗漏——原头节点还指着旧链表的第二个节点，会形成环。

## ④ 复杂度分析：数字从哪里来

| 实现 | 时间 | 空间 | 时间来源 | 空间来源 |
|------|------|------|----------|----------|
| 迭代法 | O(n) | **O(1)** | 每节点访问一次、指针改写一次 | 只用 3 个指针变量 |
| 递归法 | O(n) | **O(n)** | 每节点调用一次、常数次指针改写 | 递归调用栈深度 = n |
| 头插法 | O(n) | O(1) | 同迭代法 | dummy + 2 个指针变量 |
| 栈辅助法 | O(n) | **O(n)** | 压栈 + 弹栈各一遍 | 显式栈存 n 个节点 |

几个容易"背结论但不理解"的点：

- **为什么递归空间是 O(n)？** 递归法没有任何显式辅助结构，但每次函数调用在调用栈上占一个栈帧（保存局部变量、返回地址），最深递归到链尾，栈深度就是 n。这是**隐式空间**，也是它在大链表上会栈溢出的原因。
- **为什么迭代空间是 O(1)？** 无论链表多长，`prev / curr / next` 三个指针变量的数量恒定，不随 n 增长。
- **四种实现时间都是 O(n)，能否更快？** 不能。翻转必须触及每个节点的指针域，Ω(n) 是下界，所以 O(n) 已是最优。

<details>
<summary>💭 想一想：Go 里 10 万个节点的链表，用递归法翻转会发生什么？</summary>

**答案**：大概率栈溢出（goroutine 栈默认上限约 1GB 且可增长，但递归栈帧开销仍在；在栈更小的语言如 Java 中默认线程栈 512KB~1MB，几万层递归直接 `StackOverflowError`）。工程上链表长度不可控时**必须用迭代**。

</details>

## ⑤ 对比与选择：工程视角

| 场景 | 推荐 | 理由 |
|------|------|------|
| 生产代码 / 链表长度不可控 | **迭代法** | O(1) 空间、无栈溢出风险、常数最小 |
| 算法讲解 / 分治类变体 | 递归法 | 思想优雅，是「k 个一组翻转」等递归解法的基础 |
| 教学 / 快速手写 | 头插法 | 与直觉一一对应，不易写错指针顺序 |
| —— | 栈辅助法 | 仅在需要"先拿到全部节点再处理"的场景顺带使用，单独为翻转用它不划算 |

一句话总结：**写代码用迭代，讲思想用递归，教新人用头插。**

## ⑥ 变体与应用

翻转链表不是孤立考点，它是一族问题的"零件"：

| 变体 | 核心技巧 | 难度 |
|------|----------|------|
| 反转链表 II（反转区间 [m, n]） | 定位到 m 前驱，对区间内做头插 | Medium |
| k 个一组翻转链表 | 迭代法翻转每组 + 组间衔接 + 不足 k 组保持原序 | Hard |
| 回文链表 | 快慢指针找中点 + 翻转后半段 + 逐个比对 | Easy |
| 两两交换链表节点 | 与迭代法同构，每次处理两个节点 | Medium |
| 旋转链表 | 找到新头位置后"断开重接"，等价于局部翻转 | Medium |

以**回文链表**为例，翻转是核心步骤：快慢指针走到中点 → 翻转后半段（用本文的迭代法）→ 前后半段逐值比对 → （可选）翻转还原。整个过程可以做到 O(n) 时间、O(1) 空间。

## ⑦ 易错点清单

1. **忘暂存 next 就改指针** → 断链，后半段丢失（见 ② 的思考题）。
2. **递归法漏掉 `head.Next = nil`** → 原头节点与第二个节点成环。
3. **循环结束返回 `curr`** → `curr` 此时是 `nil`，应返回 `prev`。
4. **头插 / 栈法忘处理哨兵或尾节点** → 返回 `dummy` 而非 `dummy.Next`、尾节点 `Next` 未置空成环。
5. **边界输入**：空链表、单节点链表——迭代和头插法天然兼容，递归法依赖正确的递归基（`head == nil || head.Next == nil`）。
