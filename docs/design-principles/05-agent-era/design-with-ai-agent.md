# 用设计原则给 AI 写 Prompt：把「能跑」变成「能改」

> 一句话：**AI 只会对「当下能跑」负责；而设计原则，是你指挥 AI 写出「未来能改」的代码的词汇表。**
> 这是整个系列的收尾，也回到序章的那个问题。

---

## 回到序章的问题

序章问了：**为什么 AI 都会写代码了，你反而要懂设计原则？**

现在可以完整回答了。因为 AI 的训练目标是「给定输入，产出正确输出」，它天然只优化**当下正确**，不优化**未来可变**。它写的代码能跑、能过测试，但——

```go
// AI 大概率会这么写：能跑，但一加协议就要改它
func handle(contentType string, body []byte) {
    switch contentType {
    case "prometheus": // 解析 + 存储全塞一起
    case "influx":      // 又来一遍
    }
}
```

**「能跑」和「能改」之间，隔着的就是设计原则。** 而设计原则，恰好是你可以**明确传达给 AI 的约束**。

---

## 设计原则 = Prompt 里的「约束 DSL」

AI 不是「不懂原则」，而是**默认不启用原则**。你要做的，是把原则**显式地写进 Prompt**，变成它必须遵守的约束。

对比两种 Prompt：

**❌ 模糊的 Prompt**：

> 帮我写一个指标接入的代码。

AI 会给你一段「能跑但不可维护」的代码。

**✅ 用原则约束的 Prompt**：

> 帮我写一个指标接入模块，要求：
> 1. **单一职责**：协议解析、索引、存储三件事拆成独立接口；
> 2. **开放封闭**：新增协议时，只能新增文件，不能修改已有的接入核心；
> 3. **依赖倒置**：核心流程依赖接口，不依赖具体存储实现；
> 4. 用 Go，给出接口定义和可运行的测试。

AI 就会照着原则来写——**因为原则是可执行的、明确的约束，而「写得好一点」不是。**

<details>
<summary>💭 想一想：为什么「写得好一点」没用，而「遵守单一职责」有用？</summary>

**答案**：因为「好」是主观的、AI 无法执行；而「单一职责」「开放封闭」是**客观的、可验证的约束**——AI 可以检查「这个类是不是只有一个变化原因」「加协议要不要改核心」。**原则的价值，恰恰在于它把「好」这种模糊诉求，翻译成了 AI 能执行的明确规则。** 这就是它成为「约束 DSL」的原因。

</details>

## 用原则给 AI 下约束的模板

一个可复用的 Prompt 结构：

```
【任务】{要做什么}

【设计约束】
- 单一职责：{哪些职责必须拆开}
- 开放封闭：{哪些变化只能增、不能改}
- 依赖倒置：{哪些依赖必须面向接口}

【输出要求】
- 语言：Go
- 必须包含：接口定义 + 实现 + 可运行的单测
- 自查：逐条说明每个约束是如何满足的
```

「**自查**」是关键的一步——它逼 AI 逐条核对约束，而不是「我大概遵守了」。

---

## 用原则做 AI 代码评审

原则不仅能「指挥 AI 写」，还能「指挥 AI 审」。你可以让 AI 按原则 checklist 挑刺：

> 请按以下原则 review 这段代码，逐条给出「是否违反 + 证据 + 修改建议」：
> 1. 单一职责（是否一个类多个变化原因）
> 2. 开放封闭（加功能是否要改核心）
> 3. 依赖倒置（是否直接依赖具体实现）
> 4. 迪米特法则（是否穿越抽象摸内部）
> 5. 可测试性（能否无副作用地单测）

AI 会像一位严格的评审者，逐条用证据说话——**前提是，你得先懂这些原则，才知道该让它查什么。**

---

## 结论：原则从「束缚」变成「能力」

整个系列走完了。最后收个尾：

- **没有 AI 时**，设计原则是你「约束自己」的纪律；
- **有了 AI 时**，设计原则变成了你「约束 AI、评审 AI」的**语言和武器**。

AI 降低了「写代码」的门槛，却抬高了「写好代码」的门槛——因为现在，**判断 AI 代码好坏、指挥 AI 写出好代码的人，必须比以往更懂设计原则。**

这正是序章那句话的完整含义：

> **设计原则不是写给编译器看的，是写给「未来的你」和「你的 AI」看的。**

## 系列回顾：一条完整的学习路径

```
道 ── 六大设计原则（为什么这么设计）
  ↓
术 ── 工程实践原则（怎么衡量"好"）
  ↓
器 ── 23 种设计模式（具体怎么落地）
  ↓
用 ── 业务实践（真实场景怎么权衡）
  ↓
省 ── Agent 时代（怎么指挥 AI）
```

**你学的不是「6 条原则 + 23 个模式」，而是一种能力：面对变化，知道该往哪个方向设计、用什么招式落地、什么时候停下来。**
